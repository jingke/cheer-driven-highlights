# 算法原理与判据依据

## 1. 问题定义
输入：长视频（比赛 / 演出 / 活动），想自动定位「观众欢呼 / 掌声 / 尖叫」等
音频高潮时刻并剪出集锦。难点：素材常很大（数十 GB、数小时），且往往
**画面看不到观众**（固定机位、远景、无解说），所以**音频是唯一可靠的定位信号**。

## 2. 特征（20ms 帧，1024 点窗 @ 16k 单声道）
- `db`    : 逐帧 RMS 能量 (dB)
- `band`  : 400–3000Hz 频带能量占比 —— 人群欢呼的主能量频段
- `flat`  : 谱平坦度（→1 为噪声，低为有谐波的人声/音乐）
- `cent`  : 谱质心 (Hz)，高=尖叫/高频噪声
- `zcr`   : 过零率（高频噪声 vs 低频嗡嗡）
- `base`  : 10s 滚动 20 百分位基线 = 「当地环境底噪」

## 3. 归一化：局部 z-score（核心）
一次视频里环境底噪本身在变（人群嗡嗡、风、解说）。**绝对阈值失效**：
实测 DJI 夜场素材 `flat` 中位数仅 0.004、`cent` ~1056Hz，拍脑袋设的
硬阈值导致 0 检出。改用相对「当地 20–60s 窗口」的 z-score（累积和精确算
滚动均值/方差，O(n)），自适应且稳健。

```
score = 0.44*z(rise)        # 能量相对当地跃升（主因）
      + 0.14*z(db)
      + 0.16*z(band)        # 宽频=人群
      + 0.10*z(flat)        # 噪声性
      + 0.09*z(cent)
      + 0.07*z(zcr)
gate  = score 的 93 百分位（自适应门槛）
```

## 4. 事件归并
一次进球/精彩瞬间引发**连续多轮**欢呼，检测器会切成多个事件。按 22s 间隔
聚类：合并同一次事件的连响，又不把相邻两次独立事件粘一起。

## 5. 分级与强档筛选
- 评级 `rank = score + 0.55*multi + 0.30*wide`
  （`multi`=连续爆发轮数，`wide`=宽频占比）。S≥3.4 / A≥3.0 / B≥2.7 / C<2.7
- 强档（final_pick.py，可调）：
  - `total_cheer ≥ 6s`  ：真事件持续多轮；口哨/碰撞仅一声
  - `n_events ≥ 3`       ：连续爆发次数
  - `band ≥ 0.70`        ：宽频=人群；窄带(<0.5)=哨声/单人喊
  - `goal_est ≥ 15s`     ：排除素材开头开机噪音
  - 同源 ±20s 内只保留最强的一处

## 6. 切点
欢呼爆发点通常在事件**之后** 0.3~1.5s（人反应延迟），故片段以估计事件点
为中心：`ss = goal_est - pre_s`，`dur = pre_s + post_s`（默认前 5s 后 8s）。

## 7. 实测数据分布（DJI 夜场足球 116min）
底噪 -58dB；欢呼峰值 -14~-46dB；最大跃升 +50dB；事件间隔中位数 18~19s。
316 原始事件 → 归并 120 候选 → 强档 10。
